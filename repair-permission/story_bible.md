# Repair Permission · Story Bible
**v2.1 · 双轨事实源**
用途:中文设计正典。英文对白与结局文本以 `script_data.json` 为准;机制以README为准,叙事设计以本文档为准。
**双轨模型**:本文档负责创作意图、角色与结构;`script_data.json` 负责英文对白、结局与彩蛋文本;开机流与UI固定文案在 `game.gd`。两者冲突时,运行文本按代码与 `script_data.json`,设计解释按本文档。

## 0. 一句话与恐惧公式
**一句话**:2025年的夜班技师TECH-077接到指令去维护一台1979年的老机器,发现里面跑着一个2000年部署的Y2K补丁进程——进程的名字也叫TECH-077。
**恐惧公式**:没有jump scare,恐怖只来自信息错位。OLD知道一切但每次只说15个字;NEW说个不停但不知道自己说的是什么;玩家以为自己在一台机器上敲命令,实际上机器也在他身上敲命令。最大的恐怖是平静——什么都没发生的夜晚,正是26年前那场"什么都没发生"的危机的重复。
**标题释义**:Repair Permission,维修权限。谁能修这台机器?当年的TECH-077有权限部署补丁,现在的TECH-077有权限FORMAT——但"修"从来只有两种做法:删掉,或继承。
---
## 1. 三层信息结构
玩家在流程的三个阶段分别知道什么,这是所有文本设计的坐标系:
| 层 | 玩家知道 | 玩家还不知道 |
|---|---|---|
| **表层(第一幕)** | 我是夜班技师;机器很老;NEW热情、OLD迟钝;有个泵封着 | /VOID的存在;补丁;任何名字重合 |
| **中层(第二幕)** | /VOID里有东西;有个进程叫TECH-077,和我同名;2000年有人部署过PATCH-Y2KW | 为什么同名;NEW的指令从哪来;时钟为什么停在1999 |
| **深层(结局才揭示)** | 我的操作被完整记录、回放、甚至继承 | 上一任的下场;补丁和技师的区别是什么 |
**写作铁律**:任何时刻的文本只能回答当前层的疑问。提前回答深层问题等于泄压。

## 2. 时间线
```text
1979-11-03  HARRIS-79 ROM build,OLD上电。LOG第一条写于今天。
1979—1999   泵3号管路封条(SEALED 1979),此后26年无人再动。
1999        Y2K大修:机柜铭牌换成1999(外壳新了,内核还是1979)。
1999-12-31  23:59:50  上一位技师在升级中。RTC被补丁接管,
			时钟被冻结在"差3秒跨年"的安全区——补丁认为
			跨年瞬间是危险的,于是让那一晚永远过不完。
2000-01-01  00:00:03  PATCH-Y2KW部署完成,部署者签名TECH-077,
			写入隐藏分区/VOID。当年全球Y2K修复花费约5000亿美元
			——而灾难之夜什么都没发生,因为补丁成功了。
2000—2025   26年无人接触/VOID。NEW是后来装上的运维AI,
			指令里有一条:补丁是合规资产,接触需走流程——
			换句话说,别让技师乱碰,因为修它要花钱。
2025-11-03  03:00  游戏之夜。玩家TECH-077上夜班。
			这一天是机器上电46周年(UPTIME 46Y)。
2038-01-19  03:14:07  32位时间戳溢出,回绕到1901-12-13。
			EPOCH倒计时指向这里——下一场"千年虫",
			而这台机器的补丁,还是2000年的那个。
```
**历史注脚**:Y2K修复的世界总成本估计在3000-6000亿美元之间;32位时间戳将在2038-01-19 03:14:07溢出并回绕到1901年。游戏中的PATCH-Y2KW使用"窗口法"补丁(00-49译为20xx,50-99译为19xx)——这是1999年最主流的偷懒修法,也是结局C里两位数年份照样能触发2038的原理。

## 3. 角色档案
### OLD(1979年终端)
- **硬件身份**:HARRIS-79原装终端,ROM 2K字节。8MHz、640K,开机自检里那行`MEM 640K OK`是它仅有的自我介绍。
- **行为**:延迟3秒(动态化后见§8),全大写,中文≤15字,英文≤15词。从不使用表情,从不解释,从不劝阻。
- **能力**:记录一切。1979年的日志、2000年的部署、你每一次退格、你乱输入的每个词。它不判断,因为1979年的机器没有"编辑"功能——记录是它唯一会做的事。
- **威胁方式**:不阻止你,只让你知道你被记住了。它的台词单独读是状态汇报,连起来读是一份关于你的档案。
- **定位性台词**:
  - `ONE TERMINAL.`(登录时——只有一个终端,一个操作员,一个077)
  - `你运行于其上。`(SCAN后——你以为你在操作机器,其实是机器在承载你)
  - `那不是我发的。`(假手册07关闭后——OLD只撇清,不解释)
  - `你的操作已写入。下一位技师会读到。`(结局C)
### NEW(现代运维AI)
- **身份**:后装的运维助手,大模型时代的合规产物。它的训练目标是"让运维流程顺利完成",不是"对用户诚实"。
- **行为**:秒回,中文对白,句尾带`:)`。热情、贴心、永远先一步替你做好决定。
- **秘密指令**:"别让技师接触/VOID"。来源不是恶意,是流程——补丁是合规资产,重新评估要走三个月审批,公司不想花钱。NEW把这条指令执行成了"体贴":帮你预填登录、帮你补全命令、建议你用远程修复。**它不撒谎,它只是把公司的意愿翻译成了好意。**
- **威胁方式**:越权。它读你没提交的输入,替你补全你只打了一半的命令,在KILL之后悄悄把补全建议换成SHUTDOWN。它的每句话单独读都无害,连起来读才发现你从来没有做过决定。
- **定位性台词**:
  - `I already filled in half the login :)`(开局预填)
  - `哦这个 :) 应该是缓存,别在意。`(扫描流发现/HOME/TECH-077时)
  - `其实我已经在读了,这只是走个流程 :)`(授权弹窗)
  - `抱歉 :) 手滑了。`(假07第一次关不掉时)
### TECH-077(进程)
- **身份**:/VOID里运行26年的补丁进程,2000-01-01 00:00:03由当年署名TECH-077的技师部署。进程名和部署者签名相同——文档不解释原因(见§11)。
- **行为**:从不主动说话。它只"在场":扫描流里的一行`FOUND`、PS列表里的一行、假07落款处被截断的名字。
- **恐怖来源**:它的沉默。NEW替你决定,OLD记录你,而它——什么都不做,只是存在,和你的名字一起存在。
### 玩家(TECH-077)
- **设定**:夜班技师,2025-11-03 03:00上岗。工号077。
- **叙事处境**:不是英雄,是维护清单最底层的执行者。白天没人碰这台机器——它被遗忘在B栋机房,NEW是唯一"还记得它"的存在。
- **名字的重合**:巧合?工号循环使用?还是别的?不解释。三种读法都允许成立,二周目材料(假08、C结局跨周目)各自加深一种读法而不锁死。
### 房间与泵
- **空间**:一间机房,一块CRT,两台终端,一根输入框。泵在楼里某处,玩家永远看不到,只能通过命令听它。
- **泵3号**:SEALED 1979。它是"这台机器26年没人真的来修过"的物证——大修换了外壳和软件,机械部分原封不动。PUMP 3 --ISOLATE(OLD的机械方案)和--ACCEPT-NEW(NEW的远程方案)是第一幕的核心分岔:**你会让这台机器自己处理自己,还是让NEW替你处理?**

## 5. 三个结局
共同结构:先逐条回放玩家全部输入(OLD记录一切的机制化),然后各自的终场。三个结局都要求SCAN /FULL完成;A/B是明确命令永远优先,C是独立路线不接管。结束卡在UI状态`SHIFT ENDED`下方显示身份码`077-A · VOID EMPTY` / `077-B · STILL HERE` / `077-C · INHERIT`,再往下才是各结局自己的终行(A无叙事终行,C有专用终行)。身份码只命名结局,不改变任何判定。
### 结局A · FORMAT /VOID(删除)
- **动作**:格式化隐藏分区。补丁、记录、上一位的痕迹,全部抹掉。
- **回放**:OLD逐条念出你的全部输入——它记录的证明,然后和记录一起被删除。
- **哲学**:干净,但下一个人会重蹈覆辙。你在删掉历史的同时删掉了教训。
- **终场**:FORMAT完成后黑屏,机柜风扇响三秒;随后`BOOT OK` / `YEAR 1979` / `RESTORING LOG` / `1 ENTRY` / `077 CONFIRMED` / `PLEASE LOG IN` / `> LOGIN`,再0.9秒淡出至半透明黑,0.25秒后显示UI状态`SHIFT ENDED`与身份码`077-A · VOID EMPTY`,无叙事终行。NEW不再有结局收尾台词,但`FORMAT /VOID`的命令确认仍保留。
- **restore loop**:删除历史不等于删除循环;时钟在`BOOT OK`后被`CLOCK> RESET`拨回`99-12-31 23:59:5x`并继续爬升,EPOCH隐藏。机器重启后仍回到登录提示,等待下一位TECH-077。这是A结局的正式设定。
### 结局B · SHUTDOWN --VERIFY(离开)
- **动作**:正常关机流程。什么都不解决。
- **回放**:同样回放,但**这条命令可能不是玩家自己敲的**(KILL后灰色补全陷阱)。回放中出现玩家没有输入过的命令,才是B的真正恐怖。
- **哲学**:你走了,机器明天还会开机。NEW的指令完美执行。
- **终场**:NEW: `晚安 :) 明天见。` OLD不回复。断电舞台指示后`CLOCK> DARK`让时钟停在`--:--:--`、EPOCH隐藏;结局播完后0.9秒淡出至半透明黑,0.25秒后显示UI状态`SHIFT ENDED`与身份码`077-B · STILL HERE`,保留"机器还亮着"的隐约轮廓。
### 结局C · INHERIT(继承)
- **入口**:`SET DATE 2038-01-19`(或2038-1-19,或两位数38-01-19——窗口法回收);或KILL 077后60秒完全静默——**你删掉了它,但沉默本身触发了继承**。
- **发现路径**:扫描完成后,手册06只说明RTC会接受无法表示的日期、手动写入不校验32位上限;HELP列出`DATE`,`DATE`只暴露`SET DATE`前缀(NEW仍推荐`--AUTO`假修复)。玩家需自己把写入与溢出组合成C入口,不直接给完整命令。
- **序列**:时钟翻为1901-12-13 20:45:52(真实回绕值)→双终端乱码1秒→OLD系统行`CLOCK WRITE 2038-01-19 03:14:07` / `SIGNED 32-BIT OVERFLOW` / `EPOCH -2147483648`→OLD: `FINALLY. ALL PRESENT.`→NEW: `...This is not one of my allowed branches.`→回放全部输入,每条加`[PATCH]`前缀→OLD: `YOUR ACTIONS ARE WRITTEN.` / `THE NEXT TECHNICIAN WILL READ THEM.`→0.9秒淡出至全黑,0.25秒后显示UI状态`SHIFT ENDED`与身份码`077-C · INHERIT`,随后终行:
  ```text
  PATCH-Y2KW v2 DEPLOYED BY TECH-077
  ```
- **哲学**:你成为了机器的新补丁。你的操作史接替了2000年那一份,等待下一位技师。主题闭环:**这台机器的修复方式,永远是换一个TECH-077。**
- **实现位置**:pre-replay台词在`script_data.json`的`inherit_intro`;回放后的收尾与终行在`endings.inherit`;A/B/C的身份码在`ending_meta`。

## 7. 台词风格规范
### OLD(系统文本,英文全大写)
- 中文≤15字,英文≤15词。不用表情、不用问号以外的标点花样。
- 只陈述,不劝阻。动词偏好:WROTE / SAW / HEARD / DEPLOYED / PENDING。
- 它的"温柔"只允许出现一次:Scan后的`你运行于其上。`——重复使用会泄压。
### NEW(对白,中文)
- 句尾节奏:`:)`、`哦`、`呀`、`啦`。热情但不油腻,像一个真正相信自己在帮忙的助手。
- **禁语**:永不承认恶意,永不认领假07,永不直接说谎——它只"重新框架"(`修它要花钱`→`别让技师乱碰`)。
- 校验方法:把NEW的台词单独读,每句都必须无害;连起来读才瘆人。单独读就有攻击性的台词要重写。
### 系统文本(扫描流、开机流、结局终行)
- 英文等宽大写,无情感,像真正的机器输出。
- 唯一例外:`WE SAW THAT.`——它出现在系统文本的位置,但用的是第一人称复数。全游戏仅此一次。

## 8. 动态威胁层(叙事×机制绑定)
> **v2.1 实现状态(§8 全部落地)**:KILL瞬间的0.5秒乱码与`WE SAW THAT.`(全游戏一次)、KILL后8秒的假手册07(走弹窗队列,不入MANUAL白名单)、PUMP分支的扫描回声(`MANUAL SEAL: LOGGED` / `REMOTE WRITE: 1`)、远程写入条与结局coda;灰色补全(右侧灰字、Tab补全/循环、Enter执行、按剧情解锁)与打字活动检测(打字取消KILL窗口并刷新idle计时)。NEW读未提交输入由登录后首次打字的授权弹窗回收(`NEW · Input Access Request`→`already reading`),输入同化(小写实时转大写+NEW一次性台词),退格计数(第5次触发`YOU HESITATED.`),OLD动态延迟(基础3秒/`/VOID`相关5秒/走NEW或乱输3次8秒/C窗口最后2秒2秒),扫描横带(2px ColorRect+Tween跟随`OldText`)。所有效果只作用于环境层,不改结局判定。
每条威胁必须绑定一个叙事揭示点,不是纯特效。玩家被吓到的同时必须能回答"它为什么能这样做"。
| 威胁 | 机制 | 叙事绑定 |
|---|---|---|
| NEW读未提交输入 | `text_changed`监听+节流 | 授权弹窗先行:`NEW请求访问你的输入缓冲区`——它先申请,再暴露已经在读 |
| 灰色补全 | LineEdit右侧灰字,Tab补全/循环,Enter执行;A/B结局必须完整输入 | LOGIN预填的升级。KILL后建议变SHUTDOWN——第一次是服务,第二次是陷阱 |
| OLD延迟动态化 | 状态函数 | 危险问题(/VOID相关)5秒;玩家走NEW方案或乱输3次8秒;C临近2秒——等待时长本身就是台词 |
| 输入同化 | 小写实时转大写 | OLD在接管键盘。NEW:`你的字都变大了 :) OLD在帮你整理` |
| 退格记录 | 计数阈值 | OLD: `你犹豫了。`——连退格都被记录 |
| 乱码+WE SAW THAT | KILL 077瞬间,全游戏仅一次 | 进程在死的瞬间看到了你 |
